=== Compliance in 60 Seconds: FDA vs. EU
[.small]
* *🇺🇸 FDA 21 CFR Part 11 (US Regulation)*
** Focuses on: *"Are electronic records & signatures trustworthy?"*
** Ensures they are secure and legally equivalent to paper.
* *🇪🇺 EU Annex 11 (GMP Guideline)*
** Focuses on: *"Is the entire system validated, controlled, and compliant?"*
** Governs computerized environments, life cycles, and supplier governance.
* *The Unified Goal:* Ensure data integrity, traceability, and shift safely to audit-ready digital processes instead of paper.

[.notes]
--
Part 11 focuses on records and signatures. Annex 11 asks whether the entire system lifecycle is controlled.

=== Main Elements of 21 CFR Part 11
[.small]
* *Validation:* Systems must be formally validated to perform exactly as intended.
* *Security:* Access to electronic records must be restricted strictly to authorized users.
* *Record Retention:* Records must be securely retained in an unalterable environment.
* *Audit Trails:* Every action must be captured automatically with precise date and time stamps.
* *Electronic Signatures:* Must be completely unique and indissolubly linked to their respective records.
* *Training:* Personnel must be fully trained and accountable for working under Part 11 requirements.

== The Apache Solution

=== Apache IoTDB as a GMP Compliant IIoT Historian
[.small]
* *Purpose-Built Architecture:* Optimized specifically for high-frequency industrial sensors and PLC time-series streams.
* *Compliance Safeguards:* Built-in user authentication, role-based access control (RBAC), cryptographic encryption, and automated data retention policies.
* *Global Innovation:* Selected as one of the **Top 60 Global Innovation Cases** by the United Nations STI Forum for real-time monitoring and data preservation.

=== Core Enabler: Apache TSFile
[.small]
* *Immutable Design Patterns:* Columnar file design that is inherently append-only, ensuring historical data cannot be silently modified or manipulated.
* *Data Segmentation:* Isolated physical data layout blocks enable clean risk boundaries for validation and targeted regulatory spot-checks.
* *Ecosystem Hybridity:* TSFile plus Apache Iceberg allows complex analytical systems to track full historical query lineage and reproduce previous query states flawlessly.

=== The End-to-End Apache IIoT Pipeline
[.small]
* *Data Integration & Edge:* `Apache PLC4X` parses OPC-UA/Modbus protocols. `Apache NiFi` handles data flow and schema integration.
* *Messaging & Ingestion:* `Apache BifroMQ` serves as a high-throughput MQTT broker, passing data to `Apache Kafka` data streams.
* *Stream Processing & Rules:* `Apache Flink` or `Apache Beam` execute real-time compliance, format, and threshold validation.
* *Storage & Analytics:* `Apache IoTDB` (hot time-series database) saving as `TSFiles` directly into an `Apache Iceberg` data lake catalog, visualized safely via `Apache Superset`.

=== Reference Architecture Map
[.small]
* *Edge Layer:* Sensors / PLCs -> PLC4X -> NiFi -> BifroMQ
* *Streaming Layer:* Kafka -> Flink / Beam (Real-time data integrity filters)
* *Storage Layer:* IoTDB (Hot Storage / TSFile Engine) -> Iceberg Catalog (Cold Storage Archive)
* *Access Layer:* Superset Dashboards & Secure Auditing Tools

== Compliance and Validation

=== Compliance Considerations
[.small]
* *Annex 11 Mapping:* Matching specific clauses (e.g., electronic audit trails, automated printouts, system security) to explicit configuration profiles in Apache IoTDB.
* *21 CFR Part 11 Mapping:* Utilizing integrated user authorization matrices to manage access security and enforce unmodifiable time-stamped logs.
* *Validation Boundaries:* Clearly defining software boundaries between the underlying operating system infrastructure and containerized Apache applications.

=== Computer System Validation with GAMP 5
[.small]
* *The 9 Steps of Annex 11 Computer System Validation (CSV):*
1. Risk Assessment
2. Supplier Qualification
3. Requirements (URS)
4. Design & Specifications
5. IQ/OQ/PQ Testing
6. Data Integrity Controls
7. SOPs & Training
8. Change Control & Review
9. Operation & Monitoring

* *The 3-Tier Testing Blueprint (Step 5):*
** *Installation Qualification (IQ):* Repeatable deployment checking using reproducible container setups.
** *Operational Qualification (OQ):* Verifying failover operations, security profiles, and automated database retention policies.
** *Performance Qualification (PQ):* Simulating maximum IIoT velocity to ensure stability under load.
